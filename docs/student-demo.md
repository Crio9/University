# Студенческий стенд ДГТУ

Ветка `prototype/student-demo` основана на `prototype/opportunities-mvp`. Логотип и оформление входа взяты из `university-sprint1-frontend(1)`. FastAPI обслуживает и страницу, и API с одного адреса. Node.js на стенде не требуется.

## Запуск на ноутбуке или Linux-сервере

Нужны Git, Bash, OpenSSL и работающий Docker Compose с поддержкой `up --wait`. Из новой папки репозитория выполните:

```bash
git fetch origin
git switch prototype/student-demo
bash scripts/start-demo.sh
```

Скрипт создаёт локальный .env с новыми секретами, собирает контейнеры, применяет миграции и загружает шесть отобранных карточек. При повторном запуске использует тот же .env и базу, сохраняет изменения сотрудников. Если Docker требует sudo, скрипт запросит его для Docker. Скопированный .env старого стенда подключит старый проект/порт, если они заданы. По умолчанию новый стенд использует порт 18001. Если он занят другим проектом, поменяйте BACKEND_PORT в .env и повторите запуск.

Откройте адрес из последней строки в браузере. Ключ NVIDIA нужен только для новых импортов. Впишите NVIDIA_API_KEY в .env, затем повторите запуск. В публичном стенде используйте отдельный том и секреты: `seed.py` старого учебного стенда создаёт аккаунты с известным паролем. Скрипт подготовки студенческой версии не создаёт таких пользователей.

## Проверка с пользователями

Зарегистрируйтесь, выберите факультет ДГТУ, вложенное направление и интерес. Вкладка «Для меня» объясняет совпадения, «Все возможности» показывает весь активный каталог. На карточках открываются внешние источники. Проверьте три профиля с интересами «Бэкенд», «Фронтенд» и «ИИ и данные». Измените один интерес и обновите страницу. Вход с теми же данными должен восстановить выбор. Для учащихся доступна самостоятельная регистрация.

Стартовый каталог — редакционные пересказы публичных источников. У набора Aston выставлена дата перепроверки, у хакатона ЮKassa указан реальный дедлайн. После срока карточки скрываются. Чтобы актуализировать подборку, проверьте объявления у организаторов. Повторный запуск не продлевает даты.

## Импорт новых объявлений

На новом стенде оператор создаёт собственный привилегированный аккаунт. В каталоге проекта, в Bash:

```bash
read -rsp 'Пароль администратора (от 12 символов): ' ADMIN_BOOTSTRAP_PASSWORD
echo
export ADMIN_BOOTSTRAP_PASSWORD
docker compose exec -T -e ADMIN_BOOTSTRAP_PASSWORD backend python -m scripts.manage_roles bootstrap-admin --email operator@example.org
unset ADMIN_BOOTSTRAP_PASSWORD
```

При необходимости запускать Docker через sudo используйте `sudo --preserve-env=ADMIN_BOOTSTRAP_PASSWORD docker compose ...` в этой команде. В Swagger /docs выполните POST /api/v1/auth/login, затем Authorize с токеном сотрудника или администратора. Для загрузки партии из публичных каналов используйте POST /api/v1/ingest/sync:

```json
{"channels":["dstu_live","rndtechevents"],"limit":15}
```

Результат содержит числа полученных, добавленных и повторных сообщений. Обработка идёт в фоне; GET /api/v1/ingest/raw показывает статус и AI-разметку. Для нового оригинала с действующим сроком, городом или онлайн-форматом и призывом к участию бэкенд сверяет признаки с текстом. Подходящие карточки публикуются автоматически со ссылкой на оригинал. Неоднозначные или закрытые записи остаются в очереди сотрудника. Без ключа оригиналы остаются pending; после настройки вызовите POST /api/v1/ingest/process-pending. При недоступности Telegram используйте /ingest/import или /ingest/raw.

Чтобы разом пересмотреть прежние AI-черновики по тем же правилам:

```bash
docker compose exec -T backend python -m scripts.publish_ready
```

Операторские правки, архив и отклонённые карточки сохраняются. Исключения можно исправить через PATCH /api/v1/staff/opportunities/{raw_id}. Старое расписание, обращения и /posts/feed в этом интерфейсе не используются.

## Показ по ссылке

На ноутбуке достаточно открыть локальный адрес. Для общего стенда запустите ту же ветку на сервере с постоянным Docker volume. Направьте DNS домена на сервер, откройте порты 80/443 и задайте в установленном на хосте Caddy свой действительный домен:

```caddyfile
demo.example.org {
    reverse_proxy 127.0.0.1:18001
}
```

После применения конфигурации проверьте /health и регистрацию через HTTPS с другого устройства. PostgreSQL остаётся во внутренней сети Docker. Для перезапуска используйте docker compose up -d. Команда down --volumes удаляет базу и учётные записи.
